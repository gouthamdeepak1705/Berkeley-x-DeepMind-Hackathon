## 2. Core Data Shapes

- **`Fact`**: `{ id, label, value, formatted, unit, note }` — code computes every number; UI renders numbers exclusively via `FactValue` (expanded plain units `weeks` and `points`, clickable explanation popover).
- **`AutonomyRecordSummary`**: `{ kindLabel, level, casesCount, workedCount, provenCount, combinedGainUsd, earnRuleText, earnRuleMet, offerCard?, lostAutonomyReason? }`.
- **`EndStatementData`**: `{ generatedOn, money, noticing, wrongOrUnproven, cost, built }` where every displayed count, dollar amount, day delta, and latency holds a backing `Fact`.
- **`RecordedRunFile`**: `{ version: 1, generatedAt, seed, entries: RecordedRunEntry[] }` stored at `/recorded_run.json` (`167` live Gemini entries verified at `0` fallbacks and `0` live calls during `Watch it run` Replay in ~85s at 2x).

## 3. Simulation Rules, Gateway & Autonomy Limits

- **Chain**: **Linden & Rye** (California womenswear, USD), 8 established stores + 2 new openings (`Burlingame` Jun 1, `Napa` Aug 22).
- **One Gateway & Autonomy Limits**: By default all actions require owner approval (`"I recommend, you decide"`). Only `"Stock transfer between stores"` can earn autonomous execution — requiring the last 3 completed transfers to work, at least 1 proven against a held-out store, 0 undone, and explicit owner acceptance (**Yes, within those limits**). Once granted, single-store transfers `<= 500` units with no holdout execute automatically into **Done for you** with an **Undo** button; transfers `> 500` units still require owner approval. Any failed outcome or two consecutive Undos revoke autonomy immediately.
